# SOP · 笔记整理

> 状态：已验证
> 所属主体：wf-office 的通用流程
> 细化范围：从文章、对话或资料整理成结构化笔记
> 入口：`references/note-organization.md`
> 最后验证：2026-11-13，用《从 0 到 1 学 Vibe Coding》第 01/02 章整理任务验证

## 1. 适用与不适用

适用：把一篇文章、一段对话、一份 Markdown 或零散资料，整理成能读、能查、能复习的结构化笔记。

不适用：只改错字、只调字号或只做视觉排版；需要学习、练习或复习时先调用 `learning-material-design`，备考过程交给 `wf-study`。第一版不处理截图 OCR，遇到时先抽出文本再进入本 SOP。

## 2. 输入与输出

- 输入：纯文本、Markdown、粘贴文章；来源标题、作者、日期、原文链接有就保留，没有不编。
- 默认输出：`YYYY-MM-DD/<主题短名>/notes.md`，配图放同目录 `assets/`。
- 可选目标：思源文档、Kdocs 云文档、IMA 笔记；按“先本地、后远端”的顺序做，远端失败时本地稿仍然可用。
- 需要用户提供的信息：整理到哪篇文档；没有就说默认只写本地。

## 3. 分档

| 档 | 条件 | 行为 |
| --- | --- | --- |
| L1 快修 | 1 个来源、正文不超过 5,000 字、不改原结构、0–1 张图、自己看 | 直接整理，不写提纲，不停 |
| L2 标准 | 2–5 个来源，或 5,000–20,000 字，或需要重排章节，或 2–3 张图，或团队看 | 先给 H2/H3 提纲和图表计划，停一次 |
| L3 深度 | 6 个以上来源，或超过 20,000 字，或从零重建结构，或 4 张以上图，或对外发布，或多目标产出 | 先给方案、提纲和一段样章，停两次 |

字数按抽出的正文算，不按文件大小算。用户说“简单处理”可以降一档；对外发布不能降到 L1。

## 4. 步骤

### 4.1 定目标

1. 用户给了文档 ID、标题或链接：先解析目标，不要凭印象写。
2. 目标是父文档或笔记本顶层文档：在它下面新建子文档。
3. 目标是具体子文档：追加到末尾。
4. 同名子文档已存在：追加到已有文档，不重复新建；内容差异很大时停下来问。
5. 目标不唯一、要覆盖或删除：停下来问。
6. 没给目标：只写本地 Markdown。

思源目标先跑：

```bash
py -3 <技能目录>/scripts/siyuan_note.py resolve --title "<标题关键词>"
py -3 <技能目录>/scripts/siyuan_note.py inspect --doc <文档ID>
```

### 4.2 读全文并抽取

- 先读完再写，不边读边拼。
- 抽出六样东西：来源信息、一句话结论、章节结构、关键判断、例子和术语、可表格化的对比。
- 原文里的数字、引语、结论必须有依据；缺依据的判断删掉，不补造。
- 原文的重复段、导航、广告、推荐阅读、作者简介，不进笔记。

### 4.3 定结构（L2/L3）

- 只列 H2/H3，不写正文。
- 每个 H2 写一句“这一节让读者明白什么”。
- 标出哪里用表格、哪里用代码块、哪里需要图；没有必要的图直接删掉。
- L2 停一次；L3 再加一段 300–500 字样章，停第二次。

### 4.4 写正文

- 一个 H2 只讲一件事；H3 只拆这一件事的下一层，最多到 H3。
- 列表项先用一句加粗判断开头，再解释；不要把整段原文塞进列表。
- 对比、参数、状态、角色分工用表格；命令、JSON、配置用代码块。
- 一段只承担一个作用；连续三段都在解释同一个意思时合并。
- 不写“接下来我们来看”“综上所述”这类空转句。

### 4.5 配图

- 技术关系、流程、结构对比优先手写 SVG；需要具体物件或场景时才用 AI 插画。
- 每个 H2 最多一张图；一张图只讲一件事。
- 图片必须有 alt；文件名用英文短横线，放 `assets/`。
- 图里的标签逐个核对，错字、多字、漏字整张重做，不另贴一层文字盖住。
- 纯装饰图不加；文字已经讲清楚的关系不加。

### 4.6 写入

本地：

```text
YYYY-MM-DD/<主题短名>/notes.md
YYYY-MM-DD/<主题短名>/assets/*.svg
```

思源：

```bash
py -3 <技能目录>/scripts/siyuan_note.py create --parent <父文档ID> --title "<标题>" --file <notes.md> --dry-run
py -3 <技能目录>/scripts/siyuan_note.py create --parent <父文档ID> --title "<标题>" --file <notes.md>
py -3 <技能目录>/scripts/siyuan_note.py append --doc <文档ID> --file <notes.md>
```

先 dry-run 看目标 hpath、内容长度和图片清单，再去掉 `--dry-run`。上传图片失败时不要写入带坏图的文档，保留本地稿并说明差哪一步。

Kdocs、IMA 用各自技能写入；写完必须回读标题和正文，不能只看接口返回成功。

### 4.7 回读校验

```bash
py -3 <技能目录>/scripts/note_check.py check <notes.md>
py -3 <技能目录>/scripts/siyuan_note.py verify --doc <文档ID>
py -3 <oil-tone 目录>/scripts/tone_lint.py <notes.md>
```

- `note_check.py` 有阻断项先改再交。
- `tone_lint.py` 只给措辞提示，不替代人读。
- 思源回读看标题、表格、图片、代码块数量和首尾内容是否对得上。
- 交付说明写清：本地路径、远端位置或链接、验证了什么、哪些没验证。

## 5. 停止点

- L2：提纲确认一次。
- L3：提纲和样章各确认一次。
- 目标不唯一，或同名文档内容差异大。
- 要覆盖、删除、移动已有内容。
- 写入远端前没有明确目标。
- 图片上传失败，或图里的字核对不过。

## 6. 成稿模板

```markdown
> 来源：<作者>《<标题>》· <日期> · <原文链接，可选>
>
> 一句话：<这篇最想让人记住的判断>

![<图说明>](assets/<文件名>.svg)

## 一、<这一节让读者明白什么>

### 1. <下一层问题>

- **<判断句。>** <解释、例子或限制。>

| <列名> | <列名> | <列名> |
| --- | --- | --- |
| <内容> | <内容> | <内容> |

## 二、<下一节>
```

规则：正文不写 H1，标题由文档标题承担；来源行和一句话总结放在最前面；每个 H2 最多一张图。

## 7. 自检

- 来源、一句话、H2/H3 齐全，没有 H2 直接跳 H4。
- 没有空章节、重复标题、未闭合代码块、列数不一致的表格。
- 图片路径相对、文件存在、alt 不为空。
- 没有占位词、本机绝对路径、原文大段复制。
- `note_check.py` 无阻断项；`tone_lint.py` 的提示逐条判断过。

## 8. 失败与回退

- 目标找不到：列出候选让用户选；不猜，不新建同名文档。
- 思源连不上：保留本地 Markdown，报告端口或服务状态，不反复重试写坏数据。
- 写入成功但回读数量不对：停止继续追加，先查是不是追加到了错误文档。
- 图片上传失败：保留本地图片和相对路径，文档先不写或写完后明确标注缺图。
- 内容有争议：把不确定的句子标出来问用户，不自行补事实。
