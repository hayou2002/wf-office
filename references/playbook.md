# 办公文档工作流 · 编排手册

这里只写阶段如何交接、何时停、用什么判据。Word 专项规则在 `word.md`，内容规则在 `content-design.md`，图表在 `charts.md`，最终质量线在 `acceptance.md`。

## 名词速查

- **文档契约**：动手前对读者、目的、结论、证据、格式和验收的简短约定。
- **样章 / 样页**：用真实或脱敏内容验证结构、密度和版式的一段样稿。
- **切片**：一章、一组章节、一张表或一张图，能单独制作和验收的最小工作单元。
- **文档地图**：记录章节关系、材料来源、图表位置、责任人和验收场景的清单。
- **变更控制**：新意见先判断影响范围，再决定进入当前切片、排期还是重新确认方向。

## 进度怎么报

简单任务一句话：当前动作、真实状态、下一步。

复杂任务在阶段开始、等待用户、切片完成和受阻时更新：

```text
当前：3 / 7 · 内容与图表
状态：进行中 / 等待你确认 / 待验收 / 已完成 / 受阻 / 已超时
本步目的：先确定章节、证据和图表，再开始制作
本步产物：章节结构、证据表、图表计划
下一步：做一段样章或一张样图
```

使用子 Agent 时列：任务、目的、Agent、实际模型、状态、负责产物。拿不到模型或进度证据就写“未核实”；不编造百分比。

## 1. 判断任务与交付物

先回答：

```text
用户真正要的是一份什么文件：报告 / 纪要 / 方案 / 说明书 / 正式公文 / 其他
是新建、改内容、只改格式、校对、批量处理，还是在线协作
交付格式：DOCX / PDF / 两者
是否需要图表、目录、页码、题注、附件或模板
原稿在哪，是否有单位模板或不可改部分
谁是最终读者，什么情况下算可以交付
```

如果用户只给一句“帮我整理一下”，先判断这是内容任务还是格式任务；两者都要改时，先确认哪个优先。

校对时区分错别字、事实矛盾、术语和结构问题，只改确认范围。在线协作先确认平台、权限和版本，保留快照，编辑后导出复核；`kdocs` 不在本轮默认启用。

**停点：** 任务类型或交付格式不明确时停一次；不要先做完整文档再问。

## 2. 写文档契约

契约不超过一页：

1. 读者、场景、已有知识。
2. 读完后要做什么决定或动作。
3. 全文一句话结论。
4. 事实、来源、日期和待核实项。
5. 章节 / 页 / 表结构。
6. 模板、页数、语言、字体、图表和附件要求。
7. 验收方式：谁看、看哪些页、怎样算通过。

证据表建议：

| 事实或数字 | 来源 | 日期 | 状态 |
| --- | --- | --- | --- |
| 具体数字或判断 | 文件 / 网页 / 用户口述 | 2026-11-25 | 已核实 / 待核实 / 假设 |

来源缺失时标记“待核实”，不把模型常识写成事实。正文里的每个关键数字都应能回到证据表。

## 3. 内容架构与图表

### 3.1 建文档地图

长文或复杂材料先建：

| 章节 | 回答什么问题 | 主要证据 | 图表/表格 | 责任人 | 验收 |
| --- | --- | --- | --- | --- | --- |
| 1 | 读者为什么要看 | 来源 | 无 / 图 / 表 | 主控 / 执行者 | 用户能复述结论 |

章节按读者理解顺序排，不按资料来源堆叠。每章只解决一个主要问题。

### 3.2 图表计划

先定关系，再定图：

```text
这页要回答：哪个渠道增长最快？
关系：类别比较
图型：横向条形图
数据：财务月报，2026-01-01 至 2026-06-30
单位：万元
来源：财务月报
```

规则见 `charts.md`。需要复杂统计图时读 `create-viz` 和 `data-visualization`；本工作流脚本负责把简单可复现图表生成 PNG 并插入 Word。

### 3.3 学习材料专项

如果这份 Word 是讲义、培训手册、教程、知识库文章或自学材料，先读 [learning-materials](learning-materials.md)，再按 `learning-material-design` 做学习结果、先备知识、例子/反例、提取练习、反馈和迁移。普通报告不要套用整套教学流程。

**停点：** 长文确认章节地图；正式文件确认文种、模板和标题层级；图表确认数据来源和关系。

## 4. 做关键样章或样页

用真实或脱敏内容做一段，不要用“ Lorem ipsum ”或空占位。

样本至少包含：

- 一个真实标题层级。
- 一段正文，覆盖长句、数字和引用。
- 一个表格或一张图（如果任务需要）。
- 一个题注或页脚（如果任务需要）。
- 目标字号、行高、页边距和分页效果。

检查样本：读者能否在 30 秒内说出这一节的目的、结论和下一步？标题是否说明真实对象？图表是否回答了正文问题？

**停点：** 用户确认方向后再铺全文。局部调整继续改同一样本；整体方向变化才回到文档契约。

## 5. 分片制作

按章节、页面组或表格模块切片。每片写清：

```text
目标与产物 / 修改范围 / 共享文件负责人 / 验收标准 / 执行与审查方式
```

Word 制作顺序：

1. 建立标题、正文、题注和表格样式。
2. 写正文，事实紧跟证据表。
3. 插入表格和图表，补题注、单位和来源。
4. 统一目录、页码、页眉页脚和交叉引用。
5. 渲染当前切片并检查。

已有文档先复制，再改明确范围；图片、表格、链接、批注和嵌入对象先盘点。正式公文按需使用 `public-document-layout-master`，普通报告不要套成公文。

## 6. 分片审查

每片稳定后先审查，再进入下一片。

| 检查 | 看什么 |
| --- | --- |
| 内容 | 结论、证据、限制、行动是否完整 |
| 一致性 | 术语、数字、日期、机构名、引用和目录是否前后一致 |
| 结构 | 标题层级、目录、页码、图表编号和交叉引用 |
| 版式 | 字体、行高、缩进、页边距、溢出、遮挡、孤行标题 |
| 图表 | 数据、选型、单位、来源、图注、替代文本、渲染 |
| 文件 | 能否重新打开，原稿是否保留，输出路径是否正确 |

普通切片可由执行者自审；正式文件、长文结构、共享模板和跨章节数据需要主控或独立审查者复核。修复后只复核受影响部分。

## 7. 集成验收与交付

交付前至少做一次全文渲染，检查代表页、目录页、图表页和最后一页。

```text
文档：最终文件名与路径
内容：已核实 / 待核实 / 未取得
结构：目录 / 页码 / 题注 / 交叉引用
图表：数据来源 / 尺寸 / 题注 / 替代文本
版式：代表页渲染 / 全文渲染 / 打印预览
原稿：是否保留，输出是否为副本
未完成：没有做的验证与原因
```

如果用户要求 PDF，使用 `pdf` 做最终页面检查；DOCX 和 PDF 不一致时，说明差异并保留两者版本。

## 常见情况

### 用户临时补充意见

| 情况 | 处理 |
| --- | --- |
| 局部修正 | 进入当前切片 |
| 新章节或新图表 | 加入文档地图，安排当前或下一切片 |
| 整体方向变化 | 暂停受影响章节，重新确认文档契约或样章 |
| 与已确认规范冲突 | 列出影响和推荐选择，请用户确认 |
| 与当前目标无关 | 记入后续候选，不插队 |

### 原始材料互相矛盾

先列出矛盾点、来源和日期，不自行选一个“看起来对”的数字。能回源就回源；不能回源时在文档中标注待核实，或请用户决定采用哪一版。

### 渲染失败

先检查文件是否被 Word/WPS 占用、输出路径是否可写、字体是否缺失、渲染器依赖是否就位。保留原始 DOCX 和失败日志，不用“文件看起来没问题”代替渲染结果。

## 图表命令

```bash
py -3 scripts/render_chart.py --spec chart.json --out chart.png --html chart.html
py -3 scripts/insert_chart.py --docx report.docx --image chart.png --output report-with-chart.docx --caption "图 1 各渠道收入" --alt "柱状图：各渠道收入及数据来源" --width-cm 16
```

`render_chart.py` 支持 `bar`、`line`、`stacked_bar`；复杂图形先用 `create-viz` 生成，再用 `insert_chart.py` 插入。

## 文件与协作

- 源材料、Markdown/CSV 草稿放 `work/`；最终 DOCX/PDF 放 `outputs/`。
- 原始 Word 不覆盖；输出副本带版本或“修订”标识。
- 一个共享文件只有一个写入负责人；多 Agent 并行时用独立分支/工作区。
- 过程截图、临时渲染和缓存不默认提交 Git。
