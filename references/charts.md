# 办公图表

图表先从数据和关系出发，不从“想要一个好看的图”出发。图必须回答问题，不能替问题化妆。

## 1. 选图

| 要回答的问题 | 首选 |
| --- | --- |
| 随时间怎么变 | 折线图 |
| 谁高谁低 | 条形图；类别多时横向 |
| 排名如何 | 横向条形图，按值排序 |
| 构成是什么 | 堆叠条形图；少于 6 类才考虑饼图 |
| 分布在哪里 | 直方图或箱线图 |
| 两个变量是否相关 | 散点图 |
| 精确值是多少 | 表格 |

不要用 3D、截断柱轴、只用颜色编码或没有单位的轴。柱状图从 0 开始；时间序列可以不为 0，但要说明范围。

## 2. 数据格式

本工作流的 `scripts/render_chart.py` 接受一个 JSON：

```json
{
  "type": "bar",
  "title": "各渠道收入对比",
  "subtitle": "2026 年 1–6 月，单位：万元",
  "x_label": "渠道",
  "y_label": "收入",
  "categories": ["直营", "经销", "线上"],
  "series": [
    {
      "name": "2026",
      "values": [120, 86, 54],
      "color": "#4C72B0"
    }
  ],
  "source": "数据来源：财务月报，2026-06-30",
  "value_format": "number",
  "width": 1200,
  "height": 720
}
```

支持 `bar`、`line`、`stacked_bar`。如果需要箱线图、散点图、热力图或复杂标注，先用 `create-viz` 生成 PNG，再用插入脚本放进 Word。

## 3. 生成

```bash
py -3 scripts/render_chart.py --spec chart.json --out chart.png --html chart.html
```

脚本会：

- 校验类别、系列和值的长度一致。
- 生成可读的内联 SVG，并用浏览器截图成 2x PNG。
- 保留标题、副标题、单位、来源和轴标签。
- 不生成虚构数据。

如果只检查版式，可以加 `--html-only` 只生成 HTML，不启动浏览器。

## 4. 插入 Word

```bash
py -3 scripts/insert_chart.py --docx report.docx --image chart.png --output report-with-chart.docx --caption "图 1 各渠道收入" --alt "柱状图：2026 年直营、经销、线上收入分别为 120、86、54 万元，数据来源为财务月报" --width-cm 16
```

默认追加到文末；有固定位置时加 `--anchor "图 1"`，脚本会在包含该文本的段落后插入。原文件不覆盖。

## 5. 原生图表与图片的边界

| 产物 | 推荐 |
| --- | --- |
| Word | 高分辨率 PNG，配题注和替代文本 |
| PDF | 直接从最终 Word/HTML 渲染；图保持同一份数据 |
| Excel | 后续用 `spreadsheets` 创建原生可编辑图表 |
| PowerPoint | 后续用 `presentations` 创建原生图表；HTML 演示用 `oil-ppt` |
| 在线智能表格/文档 | 后续用 `kdocs` 的图表接口；必须回读数值 |

Word 图表不是“越可编辑越好”，而是“最终交付稳定、数据可追溯”。需要编辑数据时，同时保存 CSV/JSON 源文件和生成脚本，不把 PNG 当作唯一源。

## 6. 图表验收

- 图表标题说明结论，不只写“收入图”。
- 类别、系列、单位、时间范围和来源齐全。
- 柱状图从 0 开始，折线图的范围有说明。
- 颜色对比足够；即使黑白打印也能靠标签、线型或标记区分。
- 关键点有标注，但不把每个数据点都塞满。
- 图表与正文引用一致；正文里的数字和图上一致。
- 插入 Word 后重新渲染，检查裁切、模糊、跨页、题注和替代文本。
- 真实数据、真实来源、真实渲染三项缺一不可。
