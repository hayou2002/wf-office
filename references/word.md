# Word 专项

Word 的问题通常不在“不会加粗”，而在结构、来源、对象保护和最终渲染。先判断任务，再选工具。

## 1. 先判断是哪一种任务

| 任务 | 先做什么 | 不做什么 |
| --- | --- | --- |
| 新建文档 | 文档契约 → 标题/章节 → 正文 → 图表 → 渲染 | 不要先套模板再补内容 |
| 改内容 | 读原文 → 标出只改哪几段 → 改 → 回读 | 不顺手重写无关章节 |
| 只改格式 | 保留内容、图片、表格、批注和链接 → 套项目模板 | 不把手工加粗当作标题 |
| 校对 | 区分错别字、事实、术语、结构、格式 | 不把“文风更顺”当成修改事实的理由 |
| 批量处理 | 先做一份样本和 dry-run → 再批量 | 不直接对原目录覆盖执行 |
| 在线协作 | 先看版本、权限和评论 | 不在旧版本上直接覆盖 |

## 2. 新建或大改：先做结构

1. 写文档契约，确认读者、目的、结论、证据和验收。
2. 建章节地图：每章回答什么问题，放哪些事实、表、图和附件。
3. 先做一段样章：包含一个标题层级、一个正文段、一个图表或表格。
4. 用户确认样章后，再按章节生产。
5. 最后统一目录、页码、题注、交叉引用和格式。

标题使用 Word 的 `Title` 和 `Heading 1–3` 样式，不要用空行、空格、手工加粗或文本框冒充。长文使用自动目录，目录条目应来自真实标题；交付前更新整个目录。

## 3. 已有文档：先保护再修改

修改前至少保留一份原始副本。输出到新文件，文件名带版本或“修订”标识。

先检查：

- 页面大小、页边距、分节、页眉页脚。
- 标题层级、目录、页码和题注。
- 图片、表格、超链接、批注、嵌入对象和分页位置。
- 是否有修订痕迹、批注或未接受的格式变更。

只修改任务范围内的内容。图片、表格和嵌入式对象无法安全重排时，优先保留并报告，不要为了“统一”把它们破坏。

需要对比修改前后时，使用 `documents` 的渲染与差异能力，检查页面级变化；不要只看 XML 文本。

## 4. 版式基线

没有项目模板时，用以下基线，不把它冒充正式公文标准：

- A4，页边距按项目或单位要求；默认上下 2.0 cm、左右 2.2 cm。
- 正文中文 10.5–12 pt，行高 1.5–1.75；首行缩进 2 字符或段后距，二选一。
- 标题层级连续，一级标题、二级标题、正文和题注使用不同样式。
- 图表标题放在图下、表标题放在表上；图号、表号按全文连续编号。
- 页码从正文开始；封面和目录按项目要求处理。
- 表格跨页重复表头；数字右对齐、同列同精度，单位写在表头。
- 图片保留比例，不拉伸；图表和截图提供题注与替代文本。

正式党政机关公文另按 `GB/T 9704-2012`。只有任务明确是通知、请示、报告、函、纪要、批复、决定等正式公文时，才启用 `public-document-layout-master`；普通汇报、方案、研究材料不要伪装成国标公文。

中文标点按 `GB/T 15834-2011` 检查：中文句使用全角标点，URL、邮箱、文件路径、代码、版本号和小数保留半角。标点修复要在副本上进行。

## 5. 工具路由

| 需求 | 使用 |
| --- | --- |
| DOCX 创建、编辑、批注、目录、页码、图片、渲染 | `documents` |
| 中文正式公文/政务材料排版与结构质检 | `public-document-layout-master` |
| 文风、改写、可读性 | `oil-tone` |
| 数据图表 | `create-viz`、`data-visualization`，或本工作流图表脚本 |
| PDF 导出与版式检查 | `pdf` |
| 在线 WPS/金山文档 | `kdocs`，仅在已确认平台和权限时启用 |

`documents` 的渲染是交付门禁。任何有意义的修改批次结束后，都要重新渲染页面并检查；文本抽取通过不代表版式通过。

中文正式公文可按需运行：

```bash
py -3 <public-document-layout-master>/scripts/official_doc.py --input 原稿.docx --output "（排版）原稿.docx" --profile official
py -3 <public-document-layout-master>/scripts/doc_guard.py "（排版）原稿.docx"
```

先判明文种，再选 `official`、`red`、`minutes`、`briefing` 等版式；普通报告不要使用 `red` 或冒充红头文件。

## 6. 图表插入

数据图表先生成高分辨率 PNG，再插入 Word。一般宽度控制在 15–16.5 cm，保持原始比例；图下加题注，图内或题注注明数据来源。

使用本工作流脚本：

```bash
py -3 scripts/render_chart.py --spec chart.json --out chart.png --html chart.html
py -3 scripts/insert_chart.py --docx report.docx --image chart.png --output report-with-chart.docx --caption "图 1 2026 年各渠道收入" --alt "柱状图：2026 年各渠道收入，数据来源为财务月报"
```

需要复杂统计图、交互图或出版级图形时，先用 `create-viz` 生成并检查；Word 只接收最终 PNG。不要把可编辑数据图硬截成低分辨率图片后声称可编辑；Excel/PPT 后续再走原生图表。

## 7. 最终检查

- 文件能重新打开，标题、正文、表格和图片没有丢失。
- 目录、页码、题注、交叉引用和表格表头在最终文件中可回读。
- 代表页和图表页已渲染检查，没有溢出、遮挡、乱码、孤行标题或图表断裂。
- 事实、数字、日期、机构名、引用和来源可追溯；未核实项明确标出。
- 原稿未被覆盖；输出路径、版本和变更说明清楚。
- 只报告实际完成的验证；未跑渲染、未核对页面或未连接生产环境时，不写成已完成。
